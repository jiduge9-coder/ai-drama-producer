# QC 四层自检循环（qc-loop.md）

> 目标：用更精准的工作流减少扣款次数（提高一次通过率），逼近画面/剧情/镜头语言的高质量。
> 四层各管一段：1 管产出前、2 管交付前、3 管产出前花钱前、4 管生成后。

## 第 1 层 · 三通道审查（每条提示词，产出前）

**通道 C · 合规校验（先行，一票否决）**——分级矩阵：
- **P0 拒绝**（必须替换后才能进物料）：真实人物肖像/明星脸（含"神似某某"）、
  受版权保护的角色形象/品牌标/受保护台词、暴力血腥细节、色情暗示、平台敏感题材
- **P1 改写**（不拒绝，换可诉诸画面的替身描述）：版权角色→特征组合替身
  （"钢铁侠式战衣"→"原子朋克红金机甲战斗服，胸口弧形发光核心"）；品牌标→去标描述
- **P2 提示不阻断**：违背物理的描述→照写但标注"模型大概率无法实现，建议改写"
- 红线源头在 Gate 0 的"红线清单"（00-project-brief.md），每批物料据此复核

**通道 A · 反模式五查**（有本地反模式引擎用引擎；没有就人工过一遍）：

本地引擎探测（机器无关的发现顺序，找不到就走人工清单）：
1. 探测常见技能目录：`~/.workbuddy/skills/seedance-prompt-expert__*/seedance.py`、
   `~/.agents/skills/` 下的同类工具
2. 运行时按优先级试：`uv run -q --no-project python <engine> --check "…"` →
   `python <engine> --check "…"` → `py <engine> --check "…"`
3. 任一能出报告即用引擎；全部失败 → 人工五查（下方 1-5）
1. 抽象词：句中每个形容词能否形成具体画面？（"电影感/高级/精致/8K"→删或换物理描述）
2. 冲突指令：静止vs冲刺、昏暗vs高亮、特写vs远景等矛盾对
3. 运动叠加：≥3 个运动词 = 超载，砍到 1 镜头运动+1 主体动作+1 环境反应
4. 违背物理：模型大概率做不出的描述（瞬间换装/瞬间移动/倒放因果）
5. 高危项：画面内文字、唇形台词、高速运动、流体、多人同框——各自有规避写法（lessons.md）

**通道 B · 人工审查清单**：
- 身份不变式是否**逐字**复制（对比 03 档案，一个字都不能差）
- 动作有无开始状态+结束状态
- 皮肤段：自然纹理/哑光/无油光三件套在不在（人物特写必查）
- 文字镜头：文字内容是否已进首帧图提示词并注明"清晰无变形"
- 参考图绑定行是否按用户当前平台语法
- L6 质感标记与该时空线既定标记是否逐字一致

## 第 2 层 · 红队挑刺（每关卡交付前，模拟挑剔制片人视角）

逐份过，问出声：
- 这个镜头有故事功能吗？删掉它剧情断不断？不断 → 砍（省额度）
- 相邻镜头景别差 ≥2 级吗？（全近景连排=没有镜头语言）
- **相邻两镜的组合语义成立吗？**（两两连线过一遍，观众会读出什么第三层意思——
  顺序错了换顺序，改顺序零成本）
- **镜头趣味性自检清单过了吗？**（assets/shot-craft.md 十条：一镜一问/信息分层/
  视点切换/运动语义/前景框架/声音桥/色彩递进/定格/主动权时刻）
- **大局观咬合**：本集每个埋点在 05-series-arc.md 回收表里有归属吗？断章和下集
  开场咬合吗？
- 钩子在正确的位置吗？断章画面留问号了吗？
- 每个确认点的交付物，用户 30 秒内能看懂要确认什么吗？
- 提示词拿去直接粘贴能跑吗？有没有"大概/建议/或"式含糊残留？

红队发现问题 → 修复后才交付，不把已知的次品交给用户。

## 第 3 层 · 额度预算门（Gate 2 物料包之前）

报价单格式（贴在交付物开头，用户拍板后才产物料）：

```markdown
## 额度预算门
- 镜头总数：38（普通30/文字镜头5/对白镜头12/高危运动3）
- 每镜消耗：首图1次 + 视频1次
- 重试上限：2次/镜（预算纪律默认）
- 最坏情况：38×2×3=228 次生成
- 建议实际预算：38×3=114 次（按90%首过率+重试）
- 用户平台单价：〔用户填〕→ 预计费用：〔折算〕
```

超预算 → 回 Gate 1 砍镜头（先砍过场，钩子/情感锚保命）。

**生产硬闸门**（防意外二次扣费，借鉴 drama-skills 机制）：
- 确认与"物料包版本指纹"绑定：镜头数/时长/平台任一变更 → 旧报价作废，重新过门
- 一次性消费："继续""没问题"不算确认，必须对报价单明确拍板
- 抽卡纪律：每镜 3-5 次重摇上限；3 次不过就改镜不硬磕（成本阶梯见第 4 层）

## 第 4 层 · 生成后修复循环

用户带症状回来 → 诊断顺序：
1. 查 `lessons.md` 已知坑（大概率命中，直接给规避写法）
2. 本地反模式引擎有诊断功能就 `--diagnose "症状"`
3. 未命中 → 按 cinematic-director 类技能的失败代码手册深挖（若机器装有）
4. 按成本阶梯修，**从最便宜的开始，停在最省的那级**：

```
改提示词（0成本）→ 改参数/时长档 → 换首帧关键帧 → 改分镜（改景别/换更简单动作）
→ 剪辑补救（切头切尾/闪切/音效盖）→ 删镜头（红队判断它本来就该死）
```

同一镜头 3 次生成仍失败 → **换镜头不换提示词**：更近/更静/更简单/拆两条/改画外音/
改反应镜头。

## 失败统计反哺（技能自我进化）

每次 QC 后更新 `09-qc-log.md`；积累 ≥10 条后做聚类：
- 哪类镜头最烧钱？（→ 模板默认值改写，如多人同框默认拆正反打）
- 哪种写法一次通过率最高？（→ 提升为七段式默认写法）
- 新失败模式 → **追加进 lessons.md**（症状→根因→规避写法三段式）
- 平台行为与 platform-adapters.md 不符 → 修正该表
- **定期修剪**：每 3 个月（与适配表复查同批）过一遍 lessons.md——平台行为已变化的
  条目移入"已验证修正"归档（不硬删，防回潮），连续两个版本周期无引用的示例考虑精简。
  经验库只进不出会变成上下文包袱（社区教训：技能膨胀=质量下降）

反哺是硬要求：没有这一步，同样学费会反复交。
