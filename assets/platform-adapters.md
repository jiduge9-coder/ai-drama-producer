# 平台与模型适配表（platform-adapters.md）

> 用法：Gate 0 确认用户平台生态后，从本表取对应适配注记贴到每条提示词后。
> 提示词本体永远是**模型无关七段式核心**，适配注记是增量，不是改写。
> 本表按 2026 年中主流平台状态维护；平台能力迭代快，发现与实际不符时以用户实测为准，
> 并把差异记录进 lessons.md。

## 一、聚合平台生态（用户高频场景）

小云雀、oil oil 等聚合平台的特点：一家平台接入多家厂商模型（国内 Seedance/万相/
海螺系 + 海外 Veo/Sora 系），常有免费积分/签到额度。

适配策略：
1. 提示词按**模型无关七段式**出（最保守、最通用的写法）；
2. 每条附**主流模型适配注记**（下方速查表），用户在聚合平台里切模型时照注记微调；
3. 聚合平台的模型名会变，适配注记按"底层模型系"写（Seedance 系/Veo 系/Kling 系），
   不写聚合平台的前端包装名；
4. 免费积分策略：先用免费额度试 1 条验风格，通过后再批量——省额度第一原则。

## 四、英文镜像规则（两套编译目标）

中文七段式和英文提示词是**同一内容对两个模型的编译输出**，不是直译关系：

**编译目标 A · 中文自然语言流**（Seedance/可灵/海螺/万相等国产系）
- 七段竖线结构，行话原词（推镜/跟拍/正反打/侧逆光/浅景深/胶片颗粒），排除句用中文

**编译目标 B · 英文参数流**（MJ 及 MJ 系生图）
- 逗号短语流 + 参数尾缀（--ar 3:4 / --v 6 / --cref 角色图URL --cw 100 / --no …）
- 角色卡用 `character reference sheet + three views side by side + identical design`
  架构；纯白背景是铁律（氛围词污染=卡报废）
- 行话换行业词：推镜 push-in、跟拍 tracking shot、正反打 shot-reverse-shot、
  侧逆光 side-backlight、浅景深 shallow depth of field、胶片颗粒 film grain
- 情绪词用行为描述不用抽象词：不是 "sad"，是 "eyes down, jaw tight, slow blink"

**编译目标 C · 英文自然语言流**（Veo/Sora/Runway）
- 七段结构保持的英文叙事句，参数类要求转成描述句；负面约束写正向排除句

## 五、权重与程度词转换（从 SD 式迁移来的用户常用）

SD 括号权重在中文自然语言平台**无效**，转换表：

| SD 写法 | 中文程度词 |
|---|---|
| (word) | 比较/较为 word |
| ((word)) | 非常/很 word |
| (((word))) | 极其/极度 word |
| [word] | 略微 word（弱化） |

## 六、平台功能机会（能用就用，省额度）

- **首帧/首尾帧图生视频**：一次通过率远高于文生视频，是预算制的默认路径
- **上一镜末帧作下一镜首帧**：跨镜头衔接的最稳手段（平台支持"多图/智能多帧"时用它）
- **从白底定妆图扩展三视图/表情图**：部分平台（如小云雀）有此预设功能，需要时直接用，
  不要预生成九宫格（每格清晰度低，见 lessons.md）
- **图片模型的文字渲染**：画面内文字（招牌/信纸/屏幕字）一律在首帧图片层完成
- **原生音频台词**：Veo/Sora 系台词可原生生成；中文平台台词仍以配音后期为主流

## 七、安全与 IP（规则归 qc-loop，此处只留平台应对）

P0/P1/P2 合规分级校验矩阵统一在 `qc-loop.md` 第 1 层通道 C 执行，
源头是 Gate 0 的"红线清单"。本节只保留**平台过滤的应对写法**：

IP 名替换原则：各平台 IP 过滤强度不同，一律用"可诉诸画面"的特征组合替身，
不写名字本身——"钢铁侠式战衣"→"原子朋克复古未来主义红金配色机甲战斗服，
胸口弧形发光核心"；"BLACK SUN 风格"→"粗砺暗黑战损美学，高对比硬光"。
用户坚持要写 IP 名则照写，并在提示词末尾加"⚠️ 含 IP 名，可能被平台拦截"。
